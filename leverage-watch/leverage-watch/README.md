# 레버리지 관제

한국·미국 레버리지 및 인버스 상품 **152종**(기초자산 59개)을 매일 장 마감 후 점검하고, 조건이 모두 맞는 드문 날에만 알림을 보내는 도구입니다. 웹 대시보드에서는 각 종목이 지금 어떤 조건에서 막혀 있는지 볼 수 있습니다.

**설계 원칙: 확실히 한 방향으로 쭉 갈 때만 신호를 냅니다.**

레버리지 상품이 녹는 건 기초자산이 떨어져서가 아니라 오르내리기 때문입니다. 기초자산이 제자리로 돌아와도 2배·3배 상품에는 손실이 남습니다. 그래서 이 도구는 "얼마나 올랐나"가 아니라 **"얼마나 곧게 갔나"** 를 봅니다. 게이트 10개 중 필수 8개가 전부 통과해야 하고, 그 안에 직진성·경로 매끄러움·감가 여유가 필수로 들어 있습니다. 신호가 안 나오는 날이 대부분인 게 정상입니다.

## 빠른 시작

```bash
pip install -r requirements.txt

python selftest.py          # 규칙 엔진 자체 검증 (네트워크 불필요)
python run.py --audit       # 152종 티커가 살아 있는지 전수 확인 (처음 한 번)
python run.py --calibrate   # 실제 시장에서 직진성 임계값이 맞는지 점검
python run.py               # 점검 1회 실행
python server.py            # 대시보드 → http://127.0.0.1:8777
```

설정 전에 화면부터 보고 싶으면 `web/demo.html` 을 브라우저로 바로 여세요. 예시 데이터가 들어 있습니다.

`config.yaml` 의 `alerts` 부분만 채우면 됩니다.

**텔레그램 (권장)**
1. 텔레그램에서 `@BotFather` 에게 `/newbot` → 토큰 발급
2. `@userinfobot` 에게 아무 메시지나 보내면 본인 chat id 확인
3. 만든 봇에게 아무 메시지나 한 번 보내기 (안 보내면 봇이 먼저 말을 걸 수 없습니다)

```yaml
alerts:
  channel: telegram
  telegram:
    bot_token: "1234567:AAxxxx"
    chat_id: "987654321"
```

```bash
python run.py --test        # 연결 확인
```

디스코드는 `channel: discord` + 웹훅 URL, 아무것도 안 쓰면 콘솔 출력입니다.

알림 종류는 `notify_on` 에서 켜고 끕니다. `watch`(관심) 는 기본 꺼짐이고, 켜면 알림이 꽤 늘어납니다. `exit`(이탈) 은 켜두는 걸 권합니다.

## 계속 돌리기

**방법 1 — 서버에 스케줄러 내장 (기본)**

```bash
python server.py
```

`config.yaml` 의 `schedule.runs` 시각(기본 15:45, 06:10 KST)에 자동 점검합니다. 컴퓨터가 켜져 있어야 합니다.

**방법 2 — cron 으로 점검만 따로**

```cron
45 15 * * 1-5  cd /경로/leverage-watch && /usr/bin/python3 run.py
10  6 * * 2-6  cd /경로/leverage-watch && /usr/bin/python3 run.py
```

대시보드는 `python server.py --no-schedule` 로 띄우면 됩니다.

라즈베리파이나 상시 켜진 PC가 없다면, 노트북에서 `server.py` 를 띄워 두고 쓰다가 못 켠 날은 `python run.py` 를 수동으로 한 번 돌리면 됩니다. 상태는 파일에 저장되므로 며칠 건너뛰어도 이어집니다.

## 판정 규칙

판정은 **레버리지 상품이 아니라 기초자산 가격**으로 합니다. 레버리지 ETF 가격은 일간 리밸런싱과 액면병합 때문에 이동평균이 의미가 없습니다. 같은 기초자산을 쓰는 상품(TQQQ·QLD·SQQQ·QID·PSQ)은 결국 QQQ 추세 하나로 결정되므로 카드 한 장에 묶습니다.

### 핵심: 직진성

레버리지 상품이 녹는 건 기초자산이 떨어져서가 아니라 **오르내리기 때문**입니다. 기초자산이 제자리로 돌아와도 2배·3배 상품은 손실이 남습니다. 그래서 "얼마나 올랐나"가 아니라 **"얼마나 곧게 갔나"** 를 봅니다. 세 가지로 측정합니다.

| 지표 | 뜻 | 통과 기준 |
|---|---|---|
| 직진성 (ER60) | 60일 순이동 ÷ 실제 이동거리 합 | ≥ 0.15 |
| 경로 매끄러움 (R²) | 로그가격을 직선에 맞췄을 때 설명력 | ≥ 0.45 |
| 감가 여유 | 예상 감가 ÷ 예상 추세이익 | 감가 ≤ 추세이익 × 35% |

**직진성**은 1.0이면 완전한 직선, 0에 가까우면 왔다갔다 제자리입니다. 참고로 강한 추세는 0.33, 보통 상승장은 0.19, 같은 수익률이라도 출렁이며 오른 경우는 0.06 수준입니다.

**감가**는 근사식으로 계산합니다.

```
감가 ≈ ½ · L · (L−1) · σ² · T
```

L은 배수, σ는 20일 실현변동성, T는 보유 기간(기본 20거래일)입니다. 이 식대로면 3배는 2배의 3배로 녹고, **인버스2X는 정방향 2X의 3배**로 녹습니다. σ=50%일 때 20일 기준 2X는 2.0%, −2X는 6.0%입니다. 기초자산이 제자리여도 그만큼 사라집니다.

`--calibrate` 로 지금 실제 시장에서 이 지표들이 어떻게 분포하는지 볼 수 있습니다. 통과 종목이 0건이면 임계값이 너무 높은 것이니 전체의 10~20%가 통과하는 수준으로 맞추세요.

### 롱 진입 — 게이트 10개 전부

| | 조건 | 이유 |
|---|---|---|
| 필수 | 종가 > MA200 | 장기 추세 안에서만 |
| 필수 | 정배열 + MA200 우상향 | 횡보 중 정배열 제외 |
| 필수 | 종가 > MA20 | 단기까지 정렬됐을 때만 |
| 필수 | **직진성 ER60 ≥ 0.15** | **오르내리며 오른 건 제외** |
| 필수 | **경로 R² ≥ 0.45** | **경로가 매끄러운가** |
| 필수 | **감가 ≤ 추세이익 × 35%** | **추세가 감가를 이기는가** |
| 필수 | ATR20 ≤ 종목별 상한 | 변동성 레벨 자체의 상한 |
| 필수 | 과열 아님 (RSI<75, 이격<8%) | 급등 직후 꼭지에서 안 담기 |
| 보조 | MACD 정배열 | 모멘텀 확인 |
| 보조 | 52주 고점 대비 −10% 이내 | 추세 건강도 |

### 인버스 진입 — 게이트 10개 중 9개, 필수 8개는 전부

롱과 같은 직진성 3종에 더해: 종가 < MA200, 역배열 + MA200 우하향, 종가 < MA20, 60일 저점 이탈, 투매 구간 아님(RSI>22, 이격>−12%). 보조는 ATR 상한과 MACD 역배열입니다.

인버스가 더 빡빡한 이유는 두 가지입니다. 감가가 정방향의 3배로 붙고, 장기적으로 지수는 오르는 쪽에 베팅돼 있어 틀렸을 때 대가가 큽니다. 쿨다운도 15일로 더 깁니다.

### 시장 국면은 게이트가 아니라 거부권

종목 조건이 전부 맞아도 시장 국면이 아니면 진입 신호를 내지 않습니다. 미국은 S&P500이 MA200 위 + VIX 24 이하, 한국은 코스피200이 MA200 위 + 실현변동성 30% 이하일 때만 롱이 열립니다. 채권·원자재·크립토·변동성 그룹은 주식 국면과 따로 놀기 때문에 자기 52주 레인지 위치로 대체합니다.

### 이탈(청산) 신호

보유 중으로 기록된 종목에만 적용되고, 하나라도 걸리면 즉시 알립니다. 쿨다운 없습니다.

- MA20 2일 연속 이탈
- MA50 이탈 + MACD 음전
- 진입 시점 대비 ATR이 1.6배 이상 확대

### 중복 알림 방지

진입 알림이 나가면 그 종목은 `state/state.json` 에 보유 중으로 기록되고, 이후로는 이탈 조건만 봅니다. 이탈 후에도 쿨다운(롱 10일 / 인버스 15일) 동안은 재진입 알림이 나가지 않습니다. 실제 매매 여부와 무관하게 기록되므로, 알림만 받고 사지 않았다면 `python run.py --reset` 으로 초기화하세요.

## 대시보드 보는 법

- **맨 위 판정 밴드** — 대부분의 날에는 "오늘 행동할 신호는 없습니다"가 뜹니다. 그게 정상입니다.
- **게이트 사다리** — 카드마다 있는 9칸 막대. 굵은 칸이 필수 조건입니다. 차 있으면 통과.
- **카드 클릭** — 조건별 현재 수치가 펼쳐집니다. "왜 신호가 안 나오는지"를 보는 곳입니다.
- 상태는 **진입 / 이탈 / 보유 / 관심 / 관망 / 보류** 여섯 가지입니다. **관심**은 필수 조건이 1개 이내로 빠진, 며칠 안에 신호가 날 수도 있는 상태입니다.

## 조정하기

전부 `config.yaml` 에서 합니다. 코드는 건드릴 필요 없습니다.

**신호가 너무 안 나올 때** — `rules.long.min_gates` 를 8 → 7 로. 다만 필수 7개는 여전히 전부 필요합니다.

**종목별 변동성 상한** (`vol_max`) — 진입을 가장 많이 막는 조건입니다. 지수 ETF는 2% 내외, 개별주는 3~5% 로 잡혀 있습니다. 여기를 올리면 신호는 늘지만 감가에 당할 확률도 같이 올라갑니다.

**종목 추가** — `universe` 에 항목 하나 복사해서 `product`(표시용 티커)와 `underlying`(판정용 기초자산)만 바꾸면 됩니다.

## 알아둘 것

**한국은 삼성전자·SK하이닉스만 있습니다.** 2026년 5월 27일 상장된 단일종목 레버리지·인버스2X 16종(ETF)이 대상이고, 제도상 기초자산은 이 두 종목뿐입니다. 매수하려면 금융투자교육원에서 일반 레버리지 ETP 교육과 단일종목 심화교육을 모두 이수하고 증권사에 등록해야 합니다.

**그 상품들이 어떤 시기를 지나왔는지는 알고 시작하세요.** 상장 직후 코스피 변동성은 역사적 수준으로 올라갔습니다. VKOSPI는 6월 9일 91.2를 넘어 2008년 금융위기 고점(89.3)을 경신했고, 2026년 연평균도 57 수준입니다. 하루에 삼성전자·SK하이닉스가 10% 안팎 빠지면서 단일종목 레버리지 14종이 전부 18~21% 하락해 상장가 2만원을 밑돈 날도 있었습니다. 시티글로벌마켓증권은 국내 개인투자자의 레버리지 ETF 손실을 387억 달러(약 56조 원)로 추산했습니다. 7월 중순 이후 정부 보완조치가 나오면서 이 상품들의 거래 비중은 코스피 전체의 33.8%에서 6.4% 수준으로 줄었습니다.

이 환경이 이 도구의 규칙과 직접 맞물립니다. 변동성이 이 정도면 직진성·감가 게이트가 국내 신호를 거의 전부 막습니다. **신호가 안 뜨는 게 고장이 아니라, 그게 이 규칙이 하려는 일입니다.** 조건이 다시 맞으면 그때 알림이 옵니다.

**신규 상장 상품은 이력이 짧습니다.** 국내 단일종목 상품은 상장 두 달 남짓이라 자체 가격으로는 어떤 지표도 계산할 수 없습니다. 그래서 판정은 삼성전자·SK하이닉스 본주 가격으로 하고, 상품 가격은 표시용으로만 씁니다.

**티커는 계속 바뀝니다.** 미국 레버리지 ETF는 상장폐지·티커변경·역분할이 잦습니다. `python run.py --audit` 로 설정에 적힌 152종이 실제로 데이터를 주는지 전수 확인하고, 죽은 티커는 지우세요. MSTX는 2026년 2월 액면병합이 있었고, MSTX·MSTU 모두 최근 1년 약 −97%를 기록했습니다(같은 기간 기초자산 MSTR은 −67%). 이 격차가 바로 감가입니다.

**임계값은 합성 데이터로 정했습니다.** `er_min 0.15` / `r2_min 0.45` 는 인공 시계열로 국면별 분포를 뽑아 맞춘 값이지, 실제 시장에서 검증한 값이 아닙니다. 처음 돌린 뒤 `python run.py --calibrate` 로 실제 분포를 보고 조정하세요.

**이건 백테스트된 전략이 아닙니다.** 널리 쓰이는 추세·변동성 규칙을 보수적으로 조합한 것이고 과거 수익률로 검증하지 않았습니다. 규칙을 신뢰하기 전에 직접 검증해 보시길 권합니다.

**데이터는 yfinance 무료 소스입니다.** 국내 종목은 pykrx 로 보완하고 6시간 캐시를 씁니다. 가끔 끊기거나 값이 틀립니다. 실제 주문 전에는 HTS/MTS 로 확인하세요.

이 도구는 규칙 점검용이지 투자 자문이 아닙니다. 레버리지 상품은 하루에도 원금 전액 손실이 가능하고, 손실 책임은 전적으로 사용자에게 있습니다.

  engine.py        게이트 정의와 진입·이탈 판정
  state.py         보유 기록 · 쿨다운 · 중복 알림 차단

  index.html       대시보드
