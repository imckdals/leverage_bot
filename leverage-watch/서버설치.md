# 서버에 올리기

## 결론부터: 같은 서버에 올리세요

실측한 자원 사용량입니다.

| 항목 | 실측값 |
|---|---|
| 최대 메모리 | **86 MB** |
| 판정 연산 시간 | **3.5초** (기초자산 59개 전부) |
| 네트워크 수집 포함 | 3~6분 (하루 2회) |
| 디스크 (가격 캐시) | 약 10 MB |
| 유휴 시 CPU | 0% |

하루 두 번, 몇 분씩 도는 파이썬 프로세스 하나입니다. 이걸 위해 서버를 새로 파는 건 낭비입니다. 512MB짜리 VPS에서도 다른 서비스와 같이 돌아갑니다.

---

## 그래도 따로 파는 게 나은 경우

이 중 하나라도 해당하면 분리하세요.

- **기존 서버가 운영 중인 서비스를 돌리고 있다** — 죽으면 안 되는 게 있으면 굳이 옆에 두지 마세요. 취미 프로젝트를 상용 옆에 붙이는 건 나중에 후회합니다.
- **파이썬 버전이 3.10 미만이고 올릴 수 없다** — 기존 앱이 구버전에 묶여 있으면 골치 아픕니다.
- **기존 서버가 한국/미국 장 시간에 재부팅되거나 꺼진다** — 15:45와 06:10에 켜져 있어야 의미가 있습니다.
- **메모리가 이미 90% 이상 차 있다** — 86MB도 부담이면 분리하세요.

새로 판다면 가장 싼 등급으로 충분합니다. 1vCPU / 1GB면 넘칩니다.

## 같은 서버에 올리는 방법

### 1. venv 로 격리

이게 "같이 올려도 되냐"의 핵심입니다. 의존성이 섞이는 것만 막으면 나머지는 문제가 없습니다.

```bash
sudo mkdir -p /opt/leverage-watch
sudo chown $USER:$USER /opt/leverage-watch
# 압축 푼 파일들을 /opt/leverage-watch 로 옮긴 뒤

cd /opt/leverage-watch
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

이제 시스템 파이썬이나 다른 앱의 패키지와 전혀 섞이지 않습니다. 실행할 때는 항상 `.venv/bin/python` 을 쓰세요.

```bash
.venv/bin/python selftest.py      # 12/12 통과 확인
.venv/bin/python run.py --audit   # 티커 생존 확인
.venv/bin/python run.py           # 첫 점검
```

### 2. 포트 정하기

기본 8777입니다. 이미 쓰고 있으면 바꾸세요.

```bash
ss -tlnp | grep 8777     # 비어 있으면 아무것도 안 나옴
```

### 3. 비밀번호 설정

**대시보드에는 로그인이 없습니다.** 서버에 올려서 밖에서 볼 거면 `config.yaml` 을 고치세요.

```yaml
server:
  password: "아무도못맞출비밀번호"
```

아이디는 아무거나 넣고 비밀번호만 맞으면 됩니다. 비워두면 인증 없이 열립니다.

### 4. systemd 로 상시 실행

`deploy/leverage-watch.service` 를 열어 위쪽 3줄(`User`, `Group`, `WorkingDirectory`)만 고치세요.

```bash
sudo cp deploy/leverage-watch.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now leverage-watch

systemctl status leverage-watch          # 상태 확인
journalctl -u leverage-watch -f          # 로그 실시간
```

서비스 파일에 `MemoryMax=512M`, `CPUQuota=50%` 를 걸어뒀습니다. 혹시 폭주해도 다른 서비스를 잡아먹지 않습니다.

## 밖에서 보는 방법

### 방법 A — SSH 터널 (가장 안전, 설정 없음)

서버는 `127.0.0.1` 로만 열어두고, 볼 때만 터널을 뚫습니다.

```bash
ssh -L 8777:127.0.0.1:8777 youruser@서버주소
```

그 상태로 내 컴퓨터 브라우저에서 `http://127.0.0.1:8777`. 인터넷에 아무것도 노출되지 않습니다. 다만 휴대폰에서는 불편합니다.

### 방법 B — nginx + HTTPS (휴대폰에서 볼 거면 이쪽)

이미 nginx 가 돌고 있다면 서브도메인 하나만 추가하면 됩니다.

```nginx
server {
    listen 443 ssl;
    server_name lev.내도메인.com;

    ssl_certificate     /etc/letsencrypt/live/lev.내도메인.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/lev.내도메인.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8777;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

인증서는 `sudo certbot --nginx -d lev.내도메인.com`.

`config.yaml` 의 `server.password` 를 꼭 채우세요. HTTPS 없이 기본 인증만 쓰면 비밀번호가 평문으로 날아갑니다.

### 하지 말 것

```bash
python server.py --host 0.0.0.0     # 비밀번호 없이 이러지 마세요
```

공유기 포트포워딩으로 그냥 여는 것도 마찬가지입니다. 비밀번호를 안 넣으면 기동할 때 경고가 뜹니다.

## 서버에 올릴 때 추가로 챙길 것

**시간대.** 서버가 UTC면 `config.yaml` 의 `schedule.timezone: "Asia/Seoul"` 이 알아서 처리합니다. 확인만:

```bash
timedatectl        # Time zone 이 뭐든 상관없음. 설정값이 우선
```

**첫 실행은 오래 걸립니다.** 티커 200개를 처음 받으므로 3~6분. 이후로는 6시간 캐시를 씁니다.

**yfinance 는 비공식 소스입니다.** 서버 IP에서 요청이 몰리면 일시적으로 막힐 수 있습니다. 하루 2회면 문제된 적은 드물지만, 캐시가 오래되면 대시보드에 기준일이 옛날 날짜로 표시되니 그걸로 눈치채면 됩니다.

**디스크.** 캐시 10MB + 로그. `journalctl --vacuum-time=30d` 로 정리하면 됩니다.

**업데이트.** `config.yaml` 만 고쳤다면 재시작으로 반영됩니다.

```bash
sudo systemctl restart leverage-watch
```

## 명령어 정리 (venv 기준)

```bash
cd /opt/leverage-watch

.venv/bin/python selftest.py          # 규칙 검사
.venv/bin/python run.py               # 점검 1회 (수동)
.venv/bin/python run.py --test        # 알림 연결 확인
.venv/bin/python run.py --audit       # 티커 생존 확인
.venv/bin/python run.py --calibrate   # 직진성 기준값 점검

sudo systemctl restart leverage-watch
journalctl -u leverage-watch -n 50
```
